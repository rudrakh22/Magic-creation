\## 5. Configure npm workspaces



The root `package.json` should contain the following workspace configuration and scripts:



```json

{

&#x20; "name": "magic-creation",

&#x20; "version": "1.0.0",

&#x20; "private": true,

&#x20; "workspaces": \[

&#x20;   "apps/mobile",

&#x20;   "apps/api"

&#x20; ],

&#x20; "scripts": {

&#x20;   "dev:mobile": "npm run start --workspace=mobile",

&#x20;   "dev:api": "npm run dev --workspace=api",

&#x20;   "build:api": "npm run build --workspace=api",

&#x20;   "typecheck:api": "npm run typecheck --workspace=api"

&#x20; }

}

```



\### What these settings mean



\- `private: true` prevents publishing the root workspace as an npm package.

\- `workspaces` tells npm that the mobile and API applications belong to this repository.

\- `dev:mobile` starts the Expo development server.

\- `dev:api` starts the backend in development mode.

\- `build:api` compiles the backend.

\- `typecheck:api` checks TypeScript without emitting compiled files.



After changing workspace configuration, run:



```powershell

npm install

```

\## 8. Configure Neon PostgreSQL


Replace the placeholder locally with the actual connection string. Never commit this file or publish the connection string in screenshots, terminal recordings, documentation, or YouTube videos.

This example documents the required variable without revealing real credentials.

\## 9. Define the database schema



The initial schema defines the core Magic Creation entities, including:



\- Users and roles

\- Products and variants

\- Product requests

\- Bookings and booking items

\- Payments and webhook events

\- Inventory movements

\- Booking QR tokens

\- Magic Points and credit lots

\- Returns and exchanges

\- Audit logs and store settings



The full schema is maintained in:



`apps/api/prisma/schema.prisma`



Do not replace the full schema with a short example. The committed schema file is the source of truth.



\### Money and inventory conventions



\- Monetary values are stored as integer paise.

\- ₹2,199 is stored as `219900`.

\- Available inventory is calculated as `quantity - reservedQty`.

\- Reservations must be managed transactionally by the backend.

\- Secrets and payment credentials must never be stored in the mobile application.

\### Generate a migration preview



Prisma 7 uses `--to-schema` for the schema diff command:



```powershell

npx prisma migrate diff --from-empty --to-schema prisma/schema.prisma --script --output migration-preview.sql

```



This generates a SQL preview. It does not apply the migration to Neon.



The preview can be inspected with:



```powershell

Get-Content .\\migration-preview.sql -TotalCount 60

```



The project then uses Prisma Migrate to create and apply the actual initial migration.

\## 15. Architecture standards for future development



Future backend features will use feature-based modules:



```text

apps/api/src/

├── modules/

│   └── products/

│       ├── controller.ts

│       ├── service.ts

│       └── types.ts

├── routes/

│   └── index.ts

├── middleware/

├── lib/

│   └── prisma.ts

└── index.ts

```



Responsibilities:



\- \*\*Controller:\*\* HTTP request parsing, response formatting, and calling the service.

\- \*\*Service:\*\* Business logic, database operations, and transaction boundaries.

\- \*\*Types:\*\* Feature-specific TypeScript contracts and types.

\- \*\*Routes:\*\* Register feature endpoints and attach middleware.

\- \*\*Middleware:\*\* Shared authentication, authorization, and error handling.

\- \*\*Shared libraries:\*\* Database clients and other reusable infrastructure.



The mobile application will use TypeScript and feature-oriented Zustand stores for client-side state. Expo Router will handle screen navigation.



These standards describe the intended architecture. Each feature will be documented as it is actually implemented and tested.
